# 参考软件分析与首版取舍

## Sakura9007/Wintuner

该项目是 Python 3.13 + PyQt6 的 Windows 本地调优工具，约 9,400 行代码。主要工作区包括服务管理、系统设置、高级安全/隐私、AppX 管理和软件入口。

值得保留的设计：

- 修改服务、计划任务和注册表前保存原始状态；
- 外部命令使用白名单且默认不经过 shell；
- 系统修改串行执行，状态查询可并行；
- 使用状态 generation 防止过期查询覆盖新结果；
- 页面与后台任务有异常边界；
- 单实例和权限处理集中管理。

需要谨慎的部分是 Defender、防火墙、AMSI、VBS、BCD、BitLocker 和批量 AppX 操作。这些功能可能降低安全性或影响企业策略，因此没有进入 WinPilot 首版。

## Windows11 轻松设置 1.12

静态分析显示它是一个未签名的 .NET Windows Forms 程序，主程序约 453 KB，并包含未签名的 MinSudo、两个 Defender 批处理和 SmartScreen 注册表文件。

界面覆盖：

- Explorer、任务栏、经典右键菜单和快速系统入口；
- Windows 搜索、隐私、更新与传递优化；
- Edge、WebView2、商店 AppX 和 WinGet；
- 常用软件安装、升级和卸载；
- 内存压缩、VBS、DEP、Spectre、SysMain、BBR2 等高级选项。

其优点是入口集中、功能覆盖广、交互直接。风险在于部分恢复使用固定“默认值”，不一定等于用户修改前的值；Defender 批处理会直接更改多个安全服务的启动类型，SmartScreen 方案会删除相关 COM 注册信息。WinPilot 不采用这类实现。

## WinPilot 首版策略

- 采用 WPF 和 .NET 8，降低运行环境门槛；
- 先覆盖可解释、可检测、可逆的注册表设置；
- 每次操作保存精确原始值，不把固定默认值冒充原始状态；
- 高风险安全能力只做后续诊断入口，不提供“一键关闭”；
- AppX、服务、软件安装和系统还原点留作后续独立模块，并要求更细的预览和保护规则。

## v0.2 服务管理

第二阶段加入 11 项明确列出的可选服务。服务变更通过固定目录限制目标，外部 `sc.exe` 使用 `ProcessStartInfo.ArgumentList` 且不经过 shell。快照保存启动类型、延迟自动启动标志与运行状态；无快照时拒绝“恢复”，避免用固定值覆盖 OEM 或用户配置。RPC、事件日志、网络核心组件和 WMI 等关键服务被目录测试明确排除。

## v0.3 软件下载

第三阶段增加可预览的软件目录和本地自定义条目。内置项只使用厂商 HTTPS 下载入口；自定义项要求名称和 HTTPS 地址。下载器限制重定向次数和最大体积，使用临时文件、避免覆盖同名文件并计算 SHA-256，且绝不自动执行安装包。目录数据采用原子替换方式写入用户本地应用数据目录。

分析过程中只进行了静态读取和反编译，没有运行参考 EXE、批处理、注册表或提权程序。
